\section{Universal Scanner}
\begin{itemize}[noitemsep]
    \item Homepage input accepts a URL, domain, IP, email, message, payment link, hash, or other supported content.
    \item Automatically identify the likely input type and route it to the correct engine.
    \item Return a unified risk score, risk level, evidence, explanation, and recommended action.
\end{itemize}

\section{URL Scanner Pipeline}
\begin{itemize}[noitemsep]
    \item Validate and normalize URL $\rightarrow$ reputation/Safe Browsing $\rightarrow$ XGBoost $\rightarrow$ heuristics $\rightarrow$ domain/SSL/redirect/header analysis $\rightarrow$ risk engine $\rightarrow$ optional AI explanation $\rightarrow$ save scan $\rightarrow$ report.
\end{itemize}

\section{Risk Engine}
\begin{itemize}
    \item \textbf{Suggested starting weights:} Safe Browsing 30\%, XGBoost 30\%, domain reputation 15\%, URL heuristics 15\%, SSL/security 10\%. Validate and tune against real test data before production.
    \item \textbf{Risk bands:}
    \begin{itemize}[noitemsep]
        \item 0–19: SAFE
        \item 20–39: LOW
        \item 40–59: MEDIUM
        \item 60–79: HIGH
        \item 80–100: CRITICAL
        \item Use UNKNOWN when evidence is insufficient.
    \end{itemize}
\end{itemize}

\section{AI System}
\begin{itemize}[noitemsep]
    \item Use an \texttt{AIManager} service rather than calling providers from controllers.
    \item Gemini is primary; OpenAI is fallback.
    \item Handle 400/401/403/429, timeouts, network failures, and provider 5xx errors.
    \item Never expose API keys in logs, URLs, browser code, or user-facing errors.
    \item Use AI for explanation, summaries, and recommendations; never treat it as the sole authority for security decisions.
\end{itemize}

\section{Machine Learning}
\begin{itemize}[noitemsep]
    \item Keep the existing XGBoost model in Python.
    \item Laravel calls a Python FastAPI \texttt{/predict} endpoint.
    \item Python returns prediction/risk information. Do not rewrite the trained XGBoost model into PHP.
\end{itemize}

\section{Security Requirements}
\begin{itemize}[noitemsep]
    \item CSRF, SQL-injection protection through Eloquent/parameterized queries, XSS protection/output escaping, authentication, authorization, rate limiting, validation, secure file uploads, HTTPS, strict production CORS, secure sessions, security headers, audit logs, and secret management.
    \item Never expose stack traces, SQL errors, or API credentials to users.
\end{itemize}

\section{Privacy}
\begin{itemize}[noitemsep]
    \item Collect only necessary data. Never store plaintext passwords, OTPs, or banking credentials. Do not send passwords to AI. Minimize retention of sensitive scan content and provide clear deletion/retention policies.
\end{itemize}

\section{File Security}
\begin{itemize}[noitemsep]
    \item Validate extension and MIME type, enforce size limits, randomize storage names, keep uploads outside public directories, scan through the security pipeline, and clean temporary files.
\end{itemize}

\section{Performance \& Reliability}
\begin{itemize}[noitemsep]
    \item Redis caching, queues for long jobs, external API timeouts, selective caching, database indexes based on query patterns, optimized assets, and asynchronous processing for expensive scans.
\end{itemize}
